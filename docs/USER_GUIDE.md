# Source Insight Context & Relation 使用说明

> 面向第一次使用本插件的人：从安装、打开面板，到查调用者、调层级、右键看关系，一步步上手。  
> 插件版本：**2.0.1**　适用：VS Code 1.90 及以上

![界面总览](https://raw.githubusercontent.com/SpiritualHeart/source-insight-context-relation/main/media/preview.png)

界面布局：左侧是 **Context**（当前符号的定义代码），右侧是 **Relation**（以当前函数为根的调用者关系图）。

## 30 秒上手

1. 安装插件，并装好 **C/C++**（或 clangd）语言服务；
2. 用 VS Code 打开整个工程文件夹，等待索引完成；
3. 第一次使用：按 **Ctrl+Alt+I**（macOS：**Cmd+Alt+I**），或点击底部状态栏的 **Source Insight**，把面板打开；
4. **面板打开后，不需要再按快捷键**：把光标放到函数名或变量名上，插件会自动查询；
5. 看底部面板：左边是定义，右边是调用者/引用；
6. **双击**节点跳转，**右键**节点查看更多关系，`层级 +` 展开更深。

> 记住两点就够：**面板已经打开时，光标放到符号上就会自动更新；面板关着时，按 Ctrl+Alt+I 打开一次。**  
> 自动查询带防抖，不会每动一下光标就立刻重算，避免卡滞。

## 1. 这个插件能做什么

它把 Source Insight 4 最常用的两个窗口搬到 VS Code 底部面板：

| 窗口 | 作用 | 典型问题 |
| --- | --- | --- |
| **Context** | 显示当前函数/变量的定义、声明、类型代码 | “这个变量到底是什么类型？” |
| **Relation** | 显示谁调用了当前函数、当前函数调用了谁、变量在哪里读写 | “这个函数被哪些地方调用？” |

Relation 不是普通列表，而是可以逐层展开的树：

```text
                    ┌── APP_Model_Init
                    ├── APP_Model_SetPEPsOutputs
APP_Model_Set29COutputs ── APP_Model_Task10ms
                    └── ...
```

- 根节点是当前符号；
- 函数默认显示**调用者**；
- 变量默认显示**引用**；
- 结构体/类默认显示**成员**；
- 每个节点可以继续展开，查看“调用者的调用者”。

> 默认只显示函数/变量/成员名称，不显示文件路径和行号，界面更接近 Source Insight 的干净关系图。需要文件位置时可在设置中打开。

## 2. 安装前准备

### 2.1 确认 VS Code 版本

菜单 **Help → About**，版本需要 **1.90.0** 或更高。

### 2.2 安装语言服务（重要）

本插件本身不解析 C/C++，它调用 VS Code 的语言服务。**没有语言服务时，定义和引用关系会不准确，甚至为空。**

C/C++ 用户任选其一：

- **C/C++** 扩展：`ms-vscode.cpptools`（推荐，本文测试使用）
- **clangd** 扩展 + `clangd` 可执行文件

其他语言：

- Python：Pylance
- TypeScript/JavaScript：VS Code 内置
- Java：Language Support for Java
- 其他语言：任何实现 Definition / Reference / DocumentSymbol 的语言服务

### 2.3 打开工程文件夹

建议使用 **File → Open Folder** 打开整个工程，而不是只打开单个 `.c` 文件。

C/C++ 工程如果提示找不到头文件，需要配置：

- `compile_commands.json`，或
- `.vscode/c_cpp_properties.json` 中的 `includePath`、`compilerPath`

配置好后，等待 C/C++ 扩展完成索引。底部状态栏通常会显示解析/索引状态。

## 3. 安装插件

### 方法一：VS Code 界面安装（推荐）

1. 打开 VS Code；
2. 左侧点击 **Extensions**（扩展）图标；
3. 点击右上角 `...`；
4. 选择 **Install from VSIX...**；


6. 安装完成后点击 **Reload**（重新加载）。

```powershell
code --install-extension "D:\Desktop\ONE_PIECE\VSCODE插件\relation插件\dist-vsix\source-insight-context-relation-2.0.1.vsix"
```

安装后重新加载 VS Code。

打开扩展面板，搜索 `Source Insight`，应能看到：

```text

```

## 4. 三分钟上手

### 第 1 步：打开一个源代码文件

例如：

```text
APP_Model.c
```

### 第 2 步：把光标放到函数或变量上

例如光标放在：

```c
void APP_Model_Set29COutputs(void)
     ^^^^^^^^^^^^^^^^^^^^^^^
```

> 光标要放在**标识符**上，不要放在注释、字符串或空白处。  
> 也可以先选中函数名。

### 第 3 步：第一次打开插件面板

按：

```text
Ctrl + Alt + I
```

macOS：

```text
Cmd + Alt + I
```

或者点击底部状态栏的 **Source Insight**。

面板会出现在 VS Code 底部 **Panel** 区域，标签页名称是：

```text
SOURCE INSIGHT
```

> 这个快捷键只负责**打开/聚焦面板**，不需要每次查询都按。  
> 面板已经打开后，把光标放到符号上就会自动查询。

### 第 4 步：移动光标，自动看结果

面板打开后，直接在代码里移动光标：

- 光标放到函数名上，Relation 自动变成“调用者”；
- 光标放到变量名上，Relation 自动变成“引用”；
- 光标放到结构体/类名上，Relation 自动变成“成员”。

正常情况下会看到：

- 左边：当前函数的定义代码，定义行高亮；
- 右边：当前函数的调用者树；
- 右上角：`调用者 3 · 节点 5` 之类的统计；
- 状态栏：显示当前 Context 符号和关系数量。

第一次分析可能需要几秒钟，取决于语言服务索引是否完成。

> **为什么现在不用按快捷键？**  
> 只要面板可见、右上角眼睛按钮处于跟随状态，插件就会自动跟踪光标。  
> 面板被关闭时不会在后台反复查询；需要时再按 `Ctrl+Alt+I` 打开即可，这也能避免无谓的卡顿。

### 第 5 步：点击节点试试

- **单击**节点：在 Context 中预览这个函数/变量的定义；
- **双击**节点：直接打开源码位置；
- **右键**节点：打开关系菜单，例如“查看调用者”“查看被调用”。

| 元素 | 作用 |
| --- | --- |

| 眼睛按钮 | 开启/暂停光标跟随 |
| 刷新按钮 | 重新查询当前符号 |
| `函数` / `变量` | 当前符号类型 |

### 5.2 Context 左侧

| 元素 | 作用 |
| --- | --- |
| `定义` | 函数/变量的定义 |
| `声明` | 函数原型或 `extern` 声明（如果有） |
| `类型` | 变量的类型定义（语言服务支持时显示） |
| `‹ 1 / 3 ›` | 多个同名定义时切换匹配 |
| `‹` `›` | Context 后退/前进 |
| 锁图标 | 锁定 Context，不随光标改变 |
| 打开图标 | 打开当前定义位置 |
| 代码行 | 单击跳到对应源码行 |

### 5.3 Relation 右侧

| 元素 | 作用 |
| --- | --- |
| `关系` 下拉框 | 调用者 / 被调用 / 双向 / 引用 / 成员 / 类型 / 派生 |
| `层级` `−` `+` | 自动展开深度，1–6 层 |
| `调用者 3 · 节点 5` | 关系统计 |
| `展开` | 展开到最大层级 |
| `收起` | 收起所有已加载节点 |
| 横/纵/轮廓图标 | 切换图形布局 |
| `+`（标签栏） | 新建 Relation 视图 |
| `×`（标签） | 关闭该 Relation 视图 |
| 锁图标 | 锁定 Relation，不随光标改变 |
| 刷新图标 | 重新查询关系 |
| `‹` `›` | Relation 后退/前进 |

### 5.4 节点标记

| 标记 | 含义 |
| --- | --- |
| `◆` | 当前符号的定义（根节点） |
| `◇ 声明` | 函数声明 / 变量 extern 声明 |
| `ƒ` | 函数节点 |
| `v` | 变量节点 |
| `+` | 还有更深关系，点击按需加载 |
| `▾` / `▸` | 展开 / 收起已加载分支 |
| `×3` | 该关系出现 3 次 |
| `读×2` / `写×1` | 变量被读取/写入的次数 |
| `循环` | 检测到循环引用，节点不再展开 |
| 连接线箭头 | 从父节点指向子节点 |

## 6. 最常见的使用场景

> 下面这些操作都默认**面板已经打开**。面板打开且跟随开启时，只需移动光标就会自动刷新，不需要每次按快捷键。

### 6.1 查“这个函数被谁调用”

1. 光标放在函数名上；
2. Relation 自动切换到 **调用者** 模式；
3. 右侧每个函数节点就是一个调用者；
4. 双击节点打开调用位置。

### 6.2 查“这个函数调用了谁”

两种方法：

- 在 Relation 顶部把 **关系** 改成 **被调用**；
- 或者在函数节点上右键 → **查看被调用**。

### 6.3 查“这个变量在哪里被读写”

1. 光标放在变量名上；
2. Relation 自动切换到 **引用**；
3. 节点上的 `读×N` / `写×N` 表示读写次数；
4. 双击节点打开具体位置。

### 6.4 查“这个结构体/类有哪些成员”

1. 光标放在结构体/类名上；
2. Relation 自动切换到 **成员**；
3. 或右键结构体节点 → **查看成员**。

### 6.5 查“这个变量是什么类型”

1. 光标放在变量上；
2. 看 Context 顶部的 **类型** 按钮；
3. 或右键变量节点 → **查看类型**；
4. Relation 会切换到类型关系，类型结构体成员可继续展开。

> “类型”按钮是否出现取决于语言服务是否提供 TypeDefinition。C/C++ 的简单 typedef、匿名结构体可能只能显示声明行类型名。

### 6.6 看“调用者的调用者”

1. 先看 1 层调用者；
2. 点击工具栏 `层级 +`；
3. 或点击节点左侧 `+` 单独展开；
4. 右键节点 → **展开 2 层 / 3 层** 也可以。

### 6.7 从某个调用者继续追

在调用者节点上右键：

- **设为根节点**：以该调用者为新的树根；
- **查看调用者**：看“谁调用了这个调用者”；
- **查看被调用**：看这个调用者调用了谁。

### 6.8 固定当前关系，不让它跟着光标跑

点击 Relation 右上角的 **锁**。

锁定后：

- 光标移到别的函数，Relation 不更新；
- 仍可手动切换关系类型/层级；
- 刷新按钮仍可重新分析。

Context 也有自己的锁，两个锁互不影响。

## 7. 右键菜单详解

在 Relation 节点上点击右键：

| 菜单项 | 作用 |
| --- | --- |
| 查看调用者 | 以该节点为根，显示调用它的函数 |
| 查看被调用 | 以该节点为根，显示它调用的函数 |
| 查看引用 | 显示该节点的所有引用/调用点 |
| 查看类型 | 变量专用，显示变量类型 |
| 查看成员 | 结构体/类专用，显示成员 |
| 查看派生 | 类/接口专用，显示派生/实现 |
| 设为根节点 | 把该节点变成当前关系树的根 |
| 在 Context 中查看 | 只在左侧预览，不改变 Relation |
| 展开 1/2/3 层 | 按指定层数加载更深关系 |
| 打开定义 | 打开源码位置 |
| 复制名称 | 复制节点名称 |

> 如果 Context 已锁定，“在 Context 中查看”不会生效；需要先解锁 Context。

## 8. Context 窗口

### 8.1 显示内容

- 函数：从函数签名开始的完整定义；
- 变量：定义行附近上下文；
- 结构体/类：定义体；
- **目标函数名/变量名会单独高亮**，定义行同时有背景色和左侧标记；
- 超长函数会截断，并显示“下方已省略”等提示。

### 8.2 切换定义/声明/类型

顶部三个按钮：

- **定义**：函数体/变量定义；
- **声明**：函数原型或 `extern` 声明；
- **类型**：变量的类型定义。

没有对应内容的按钮会隐藏或禁用。

### 8.3 多个同名定义

如果语言服务返回多个定义，Context 顶部会出现：

```text
‹ 1 / 3 ›
```

点击左右箭头切换。

### 8.4 跳转

- 单击代码任意行：打开该行；
- 点击“打开定义”：打开当前定义位置；
- 点击“复制名称”：复制当前符号名。

### 8.5 锁定与历史

- 锁图标：锁定后 Context 不跟随光标；
- `‹` / `›`：在预览过的 Context 之间后退/前进。

## 9. Relation 窗口

### 9.1 关系类型

| 类型 | 适合 | 显示内容 |
| --- | --- | --- |
| 调用者 | 函数 | 谁调用了当前函数 |
| 被调用 | 函数 | 当前函数调用了谁 |
| 双向 | 函数 | 左侧调用者，右侧被调用 |
| 引用 | 函数/变量 | 所有引用位置，按引用者函数聚合 |
| 成员 | 结构体/类/命名空间 | 成员 |
| 类型 | 变量 | 变量类型 |
| 派生 | 类/接口 | 派生类/实现 |

默认关系：

- 函数 → 调用者
- 变量 → 引用
- 结构体/类 → 成员

### 9.2 层级

- `层级 1`：只显示直接调用者/被调用者；
- `层级 2`：再展开一层；
- 最大 6 层；
- 节点左侧 `+`：只加载这个节点的下一层；
- 节点左侧 `▾ / ▸`：收起/展开已经加载的分支。

> 层级越大、工程越大，查询越慢。大工程建议先用 1 层，按需点 `+`。

### 9.3 节点上的数字

- `×3`：同一关系出现 3 次；
- `读×2`：变量被读取 2 次；
- `写×1`：变量被写入 1 次；
- 没有数字表示只出现 1 次。

### 9.4 单击、双击、右键

| 操作 | 结果 |
| --- | --- |
| 单击节点 | 在 Context 预览该节点定义 |
| 双击节点 | 打开源码位置 |
| 右键节点 | 打开关系菜单 |
| 点击 `+` | 加载更深关系 |
| 点击 `▾`/`▸` | 收起/展开已加载分支 |
| Enter（节点聚焦时） | 打开源码 |

## 10. 多标签、布局和图形选项

### 10.1 新建 Relation 视图

点击 Relation 顶部标签栏右侧的 `+`：

- 新标签复制当前关系类型和层级；
- 每个标签独立保存关系类型、层级和树；
- 切换标签时，如果该标签的根不是当前符号，会按当前符号重建；
- 最多 6 个标签；
- 只有一个标签时不显示 `×`。

典型用法：

- 标签 1：调用者；
- 标签 2：被调用；
- 标签 3：引用。

### 10.2 布局

Relation 顶部有三个布局按钮：

| 图标 | 布局 | 适合 |
| --- | --- | --- |
| 横向树 | 从左到右 | 调用链、截图 |
| 纵向树 | 从上到下 | 窄面板 |
| 轮廓列表 | 缩进列表 | 快速浏览、长名字 |

也可以使用命令：

```text
Source Insight: 下一个 Relation 视图布局
```

循环切换三种布局。

### 10.3 图形线型

在设置中搜索 `sourceInsight.relation`：

- `relationLineStyle`：`elbow`（折线）/ `curve`（曲线）/ `direct`（直线）
- `relationSpacing`：节点列间距
- `relationArrows`：是否显示箭头
- `relationNodeShadow`：节点阴影

## 11. 设置建议

打开设置：

```text
Ctrl + ,
```

搜索：

```text
@ext:onepiece-tools.source-insight-context-relation
```

或使用命令 **Source Insight: 打开设置**。

### 11.1 最常用设置

| 设置 | 默认 | 建议 |
| --- | --- | --- |
| `sourceInsight.followCursor` | `true` | 想手动看图时关掉 |
| `sourceInsight.trackingMode` | `symbol` | 跟踪函数/变量；`enclosing` 跟踪所在函数；`off` 关闭 |
| `sourceInsight.autoReveal` | `false` | 不想每次弹面板就保持关闭 |
| `sourceInsight.defaultDepth` | `1` | 大工程保持 1 |
| `sourceInsight.showLocations` | `false` | 需要文件位置时打开 |
| `sourceInsight.contextLineNumbers` | `true` | 不需要行号可关闭 |
| `sourceInsight.maxRelationNodes` | `500` | 卡顿时降到 200–300 |
| `sourceInsight.maxReferences` | `300` | 大工程可降到 100–200 |
| `sourceInsight.excludeMacros` | `false` | C 工程宏太多时打开 |
| `sourceInsight.excludedSymbols` | `[]` | 填不关心的大函数名 |
| `sourceInsight.relationLineStyle` | `elbow` | 折线/曲线/直线 |
| `sourceInsight.relationSpacing` | `40` | 节点列间距 |
| `sourceInsight.relationArrows` | `true` | 想要更干净可关闭 |
| `sourceInsight.relationNodeShadow` | `true` | 喜欢扁平可关闭 |

### 11.2 大工程推荐

```jsonc
{
  "sourceInsight.defaultDepth": 1,
  "sourceInsight.maxRelationNodes": 300,
  "sourceInsight.maxReferences": 200,
  "sourceInsight.autoReveal": false,
  "sourceInsight.followCursor": true,
  "sourceInsight.excludeMacros": true,
  "sourceInsight.showLocations": false
}
```

### 11.3 想看到文件位置

默认为了保持干净，不显示文件路径。需要时打开：

```jsonc
{
  "sourceInsight.showLocations": true
}
```

节点名称下方会显示位置；这不是 Source Insight 的独立列，而是节点内的辅助行。

## 13. 故障排查

### 13.1 面板打开是空白

| 可能原因 | 处理 |
| --- | --- |
| 光标不在符号上 | 把光标放到函数/变量名上 |
| 文件未保存 | 先保存 |
| 语言服务还在索引 | 等待几秒，点击刷新 |
| 没有安装语言服务 | 安装 C/C++ 或 clangd |
| 打开的是单文件而非工程 | 用“打开文件夹”打开工程 |
| 文件类型不支持 | 确认语言服务已启用 |

### 13.2 提示“未找到符号”或“未找到定义”

- 确认光标位置在标识符上；
- 确认文件已保存；
- C/C++ 工程检查 `includePath` 和 `compilerPath`；
- 打开输出面板，选择 **Source Insight** 查看是否有超时日志；
- 尝试 **Source Insight: 刷新当前符号**。

### 13.3 调用者列表为空

- 函数可能确实没有被调用；
- 调用可能通过函数指针、宏或回调，语言服务无法解析；
- C/C++ 索引未完成；
- 引用提供者不可用；
- 尝试降低层级、刷新，或安装/切换语言服务。

### 13.4 关系图很慢

- 把 `defaultDepth` 改为 1；
- 降低 `maxRelationNodes`；
- 降低 `maxReferences`；
- 用 `excludedSymbols` 排除不关心的大函数；
- 关闭 `autoReveal`；
- 不要点“展开到最大层”，改用节点上的 `+` 按需加载。

### 13.5 没有“类型”按钮

- 当前符号不是变量；
- 语言服务没有提供 TypeDefinition；
- 语言服务没有返回独立的类型位置（例如部分内置类型或匿名结构体）；
- 可在 Context 中直接看声明行的类型名。

### 13.6 看不到文件路径

这是默认行为。打开：

```jsonc
{
  "sourceInsight.showLocations": true
}
```

### 13.7 光标移动时面板不更新

检查：

- 眼睛按钮是否处于开启状态；
- Context / Relation 是否被锁定；
- `trackingMode` 是否被设为 `off`；
- `followCursor` 是否为 `false`；
- 面板是否可见（关闭时默认不更新，除非开启 `autoReveal`）。

### 13.8 右键没有菜单

- 右键要点在节点卡片上，不要点在空白区域；
- 如果节点没有可分析符号，执行关系项时会提示“该节点没有可分析的符号”；
- 先单击节点选中，再右键。

### 13.9 面板关掉了怎么重新打开

点击底部状态栏的 **Source Insight**，或按 `Ctrl+Alt+I`。

### 13.10 安装失败

- 确认 VS Code 版本 ≥ 1.90；
- 确认 VSIX 文件完整；
- 在扩展面板选择 **Install from VSIX**；
- Windows 路径含中文/空格时，命令行安装请给路径加引号。

## 14. 常见问题

**Q：插件会修改我的代码吗？**  
A：不会。它只读取语言服务返回的定义/引用信息，不写工程文件。

**Q：需要先编译工程吗？**  
A：不需要完整编译，但 C/C++ 语言服务需要知道 include 路径。`compile_commands.json` 能显著提高准确性。

**Q：支持 C++ 吗？**  
A：支持。类成员、派生、引用等能力取决于 C/C++ 扩展的 DocumentSymbol / Implementation Provider。

**Q：支持 Python、TypeScript 吗？**  
A：使用 VS Code 标准 Provider，理论上支持；调用者/被调用树的质量取决于语言服务是否提供准确引用。

**Q：为什么节点上只有名字，没有文件名和代码片段？**  
A：这是为了对齐 Source Insight 的干净关系图并减少干扰。文件位置可在设置中打开。

**Q：需要每次按 `Ctrl+Alt+I` 吗？**  
A：不需要。快捷键只负责打开/聚焦面板；面板已经打开且跟随开启时，光标移动到符号上就会自动查询。面板关闭后不会在后台反复查询，需要时再打开一次即可，这也能减少无效分析。

**Q：为什么自动查询没有立刻刷新？**  
A：插件内置防抖（默认 `debounceMs = 280` 毫秒），光标快速移动时会等停顿后再分析，避免每动一下就重算导致卡顿。大工程可在设置中适当调大。

**Q：为什么调用者只有一层？**  
A：默认 `defaultDepth = 1`。点 `+` 增加层级，或点击节点左侧 `+` 按需展开。

**Q：为什么同一个函数出现多个节点？**  
A：它可能从不同调用点被调用，或者位于不同分支；节点上的 `×N` 表示出现次数。

**Q：Context 锁和 Relation 锁有什么区别？**  
A：Context 锁只固定左侧定义；Relation 锁只固定右侧关系图，互不影响。

**Q：多个标签会同时跟随光标吗？**  
A：只有当前活动标签自动更新；切回其他标签时，会按当前符号和该标签的关系类型/层级重建。Context 和锁是全局共享的。

**Q：能导出关系图吗？**  
A：可以用 **Source Insight: 复制关系树为文本** 复制成缩进文本，粘贴到文档或工单中。

## 15. 五分钟检查清单

第一次使用时按下面顺序检查：

- [ ] VS Code 版本 ≥ 1.90
- [ ] 已安装 C/C++ 或 clangd 语言服务
- [ ] 用“打开文件夹”打开了工程
- [ ] C/C++ 索引已完成
- [ ] `Ctrl+Alt+I` 能打开底部面板（只需第一次）
- [ ] 面板打开后，光标放在函数/变量名上会自动刷新
- [ ] Context 能看到函数定义
- [ ] Relation 默认显示调用者/引用/成员
- [ ] 双击节点能跳转
- [ ] 右键节点能看到关系菜单
- [ ] `层级 +` 能展开更多层
- [ ] 锁图标能固定当前视图
- [ ] 需要文件位置时已打开 `showLocations`

全部通过后，基本就可以按 Source Insight 的习惯使用了。
